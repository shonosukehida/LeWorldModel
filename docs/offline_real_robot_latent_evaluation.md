# Saved real-robot JEPA latent distances

`offline_real_robot_latent_eval.py` reads an existing `rollout.h5` without importing
`eval_real_robot.py` or connecting to robot/camera/GELLO hardware. No DP model is loaded.

```bash
.venv/bin/python offline_real_robot_latent_eval.py /path/to/experiment/rollout.h5 \
  --wm-checkpoint /path/to/exact/model_object.ckpt \
  --wm-stats ~/.stable_worldmodel/datasets/flip_mug/ep100_tm300_multiview_play_normal_brightness/process_stats.npz \
  --image-size 224 --device cuda
```

Use the exact checkpoint and `eval.img_size` used for the original run. The CLI
checks the saved config's policy run, image size, statistics, and random-encoder flag.
For directory policy references the recorded config cannot establish which historical
checkpoint was loaded; the caller must supply the correct exact file. A checkpoint
or statistics file replaced after recording cannot be detected from the old config.
Statistics paths must match, or both files must exist and have identical SHA256.
Missing statistics never trigger recomputation. DP training statistics must not be used.

Images must be stored as `(T,H,W,3)`, proprio as `(T,8)`, and the fixed goal as two
`(H,W,3)` images plus `(8,)` proprio. Observation and Goal resolutions may differ, including between cameras; each image independently passes through the existing WM resize preprocessing. No source images are reshaped or resized during validation. All required inputs must be finite. A fixed
goal is encoded once with `GPCPolicy.encode_goal`; each observation uses the same
GPC preprocessing and WM encoder. Latents must be finite `(1,1,D)`; the final time
latent is used without flattening, pooling, concatenation or extra normalization.
The reported distance is ordinary L2, not the GPC negative squared reward.

Default outputs are in `latent_eval/` beside the input:

- `observed_latent_distance.png`
- `latent_distance.h5`: `step_idx`, `observed_latent_distance`, `observed_latents`, `goal_latent`
- `latent_distance_metrics.json`: exact paths/hashes, versions, device, preprocessing,
  original config, UTC execution time, step count and latent dimension

Existing output directories are reused. The three evaluation files above are generated in a temporary directory, then replaced with the new results; unrelated files are preserved. Use `--output-dir /path/to/new/directory`
for another evaluation and `--max-steps 3` for a small smoke test. `--device cpu`
is supported. Step indices enumerate saved observation rows starting at zero.
Model evaluation uses inference mode and preserves NumPy/Torch RNG states.

8-step prediction comparison is omitted: the rollout stores observations and
commands, and the optional GPC visualization archive stores candidate actions,
rewards and selected indices, without the corresponding predicted latent vectors
and verified execution endpoints. Predictions are not reconstructed or presented
as predictions saved during execution.

Hardware-free tests:

```bash
MPLCONFIGDIR=/tmp/lewm-mpl .venv/bin/python -m unittest discover -s tests -p 'test_offline_real_robot_latent_eval.py'
```

The training, control loop, HDF5 format, checkpoints and source rollouts are unchanged. The real-robot entry point adds only an optional post-save hook and opt-in checkpoint provenance capture. Reproducibility requires identical
checkpoint/statistics/input contents and software/device backend; no global
backend determinism settings are changed.


## Automatic evaluation after real GPC execution

```yaml
eval:
  real_robot:
    latent_visualization:
      enabled: true
```

The default in `config/eval/flip_mug.yaml` is `false`; omitted settings also disable
it. It runs only for `policy_type: gpc`, `execute: true`, `dry_run: false`.
The existing WM loader is retained. When enabled, the same checkpoint resolution
is pinned to an exact object file and recorded together with the actual WM
statistics path/hash and image size. Persisted statistics are required and must
match loaded WM processors; no replacement statistics are generated by this feature.

The hook runs in `run_xarm_task` after `_run_xarm_task_with_env` completes its legacy
persistence and the outer `env.close()` is attempted. This also permits evaluating
saved partial observations after a control exception. The original control exception
propagates; auxiliary exceptions print a labeled type/message and full traceback.
If an earlier legacy persistence operation fails, only files already saved can be
used. This feature does not change or repair legacy save/stop failure behavior.

Evaluation reuses a private deep copy of the loaded WM, normalization processors,
and image transforms. DP and robot environment are not copied. Original model
buffers, caches, train/eval state and RNG state are preserved. This requires memory
for an additional model copy after the robot closes; insufficient memory is reported
as an auxiliary error. Existing `latent_eval/` directories are reused, refreshing only the three evaluation output files.

Run the hardware-free tests (including real GPC preprocessing with synthetic images):

```bash
MPLCONFIGDIR=/tmp/lewm-mpl .venv/bin/python -m unittest discover -s tests -p 'test_*real_robot_latent*.py'
```
